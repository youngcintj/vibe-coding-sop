# Vibe-Coding SOP 跨 AI 评审 · 使用说明

## 3 个 AI 怎么挑

| AI | 强项 | 适合评什么 |
|---|---|---|
| **ChatGPT** | 结构化输出、JSON 严格 | 拿"标准化 7 维度评分" |
| **Claude** | 深度推理、二阶效应 | 拿"为什么这是问题"的深度分析 |
| **Gemini** | 多视角对比、矩阵化 | 拿"跨文件一致性矩阵"+ "跟同类 SOP 对比" |

**3 个全跑** = 拿全 3 个视角,最稳。
**1 个就够** = 选 Claude(深度最强)或 Gemini(覆盖最全)。

## 5 步使用流程

### Step 1: 准备
- 下载 `vibe-coding-sop-dist.zip`(在工作区 `/Users/yangyangchen/.minimax-agent-cn/projects/vibe-coding-sop/`)
- 准备 3 个 AI 账号(或者用已有的)

### Step 2: 跑评审
- 打开 `01-chatgpt.md`,复制"```"之间的内容,粘贴到 ChatGPT,上传 zip,发送
- 打开 `02-claude.md`,同上跑 Claude
- 打开 `03-gemini.md`,同上跑 Gemini

### Step 3: 保存结果
新建 `results/` 目录,保存 3 份原始回复:
```
results/
├── chatgpt-eval-2026-07-23.md
├── claude-eval-2026-07-23.md
└── gemini-eval-2026-07-23.md
```

### Step 4: 对比分析
写 `comparison-2026-07-23.md`,对 3 份结果:

| 维度 | ChatGPT | Claude | Gemini | 一致性 |
|---|:---:|:---:|:---:|:---:|
| 整体评分 | X | Y | Z | 偏差大/中/小 |
| 必改 1 | ... | ... | ... | 3 个都提 / 2 提 / 1 提 |
| 必改 2 | ... | ... | ... | ... |
| ... | ... | ... | ... | ... |

**关键看**:
- **3 个都提的必改** → 100% 要改
- **2 个提的** → 80% 要改
- **1 个提的** → 50% 看情况

### Step 5: 写修改计划
基于对比结果,写 `v2-modification-plan.md`:

```markdown
# Vibe-Coding SOP v2 修改计划

## 必改(3 个 AI 都提的)
- [ ] **必改 1**: ...
- [ ] **必改 2**: ...

## 建议改(2 个 AI 提的)
- [ ] **建议 1**: ...

## 看情况改(1 个 AI 提的)
- [ ] **看情况 1**: 触发条件 → ...

## 不改
- 3 个 AI 都没提的:保持
```

## 评审结果的"质量检查"

不是所有 AI 评审都靠谱,先检查这几点再采纳:

| 检查项 | 怎么验 |
|---|---|
| **行号对吗** | 打开对应文件,跳到行号,看原文是不是 AI 说的 |
| **引文准吗** | AI 引的"原文片段"跟实际内容是否一致 |
| **问题真吗** | 在脑子里跑一遍"在 X 场景下确实会遇到"吗 |
| **建议可执行吗** | 改完不会引发新问题吗 |
| **置信度标了吗** | AI 明确说"高/中/低 信心"了吗(没标的降权) |

## 评审完的下一步

1. **v2 修改**:基于评审写 v2(改 docs)
2. **再评审**:v2 改完再跑一次 3 AI,看问题是不是修了
3. **实战测试**:拿一个真任务(比如 office-pincer 漫画)按 v2 跑一遍
4. **v3**:基于实战反馈出 v3

## 注意事项

- **不要盲信 AI 评审**:它会幻觉,会过度同意,会泛泛而谈
- **要交叉验证**:3 个 AI 都提的问题,基本是真的
- **要 PM 视角**:PM 不在乎技术细节,在乎"团队能用 / 不会卡"
- **要花时间复核**:每条"必改"都要打开文件看一遍,5 分钟的事,别省

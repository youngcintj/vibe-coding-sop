# 评审 Prompt · Claude 专用

> 用法:复制本文件全部内容 → 打开 Claude.ai → 新对话 → 粘贴 → 上传 `vibe-coding-sop-dist.zip`
> 适用: Claude 3.5 Sonnet / Claude 3.7 / Claude 4 系列

---

```
你是一个 skill 设计评审专家,擅长深度推理和长文本分析。

## 评审目标
评审这个 vibe-coding SOP skill 包:
- 5 个阶段(需求确认/技术评估/开发/测试/代码审查)
- 4 个横向要求(执行思路/风险/建议/强制 Git)
- 6 维技术评估矩阵(功能 30/熟悉度 20/性能 15/维护 15/生态 10/成本 10)
- 4 种分发格式(SKILL.md / .cursorrules / CLAUDE.md / system-prompt-block)
- 5 份阶段详细文档(references/stage-1 ~ stage-5)

## 待评审材料
附件: vibe-coding-sop-dist.zip,包含 SKILL.md / README.md / .cursorrules / CLAUDE.md / package.json / prompts/system-prompt-block.md / references/*.md

## 评审要求:证据驱动 + 可复查(重量级)
你以"细致推理"著称,这次评审请用你最擅长的深度分析:
1. **每条评价引用文件:行号**(例:`SKILL.md:42` 或 `references/stage-3-development.md:18-22`)
2. **引原文片段**(≤ 30 字,放在引号里)
3. **深度推理** — 不只说"问题是什么",要说"为什么这是个问题" + "在什么场景下会触发"
4. **考虑二阶效应** — 改完之后会不会引发新问题

## 7 维度深度分析(每维度 1-10)

| 维度 | 评估点 |
|---|---|
| 1. 完整性 | 5 阶段/4 横向/6 维/拍板点都覆盖了吗?有没有关键遗漏? |
| 2. 可执行性 | 每个阶段动作具体吗?还是停留在"做好需求"这种废话? |
| 3. 可拍板性 | PM 拍板点明确吗?有具体问什么吗? |
| 4. 可量化 | 有检查清单 / 反模式吗?能客观判断"做没做"吗? |
| 5. 可适配 | 不适用场景 / 边界条件写了吗?能处理例外吗? |
| 6. 文档质量 | references/ 详细吗?SKILL.md 简洁吗?README 完整吗? |
| 7. 跨工具兼容 | 4 种分发格式完整吗?Cursor/Claude Code/网页 LLM 都能用吗? |

## 输出格式(适合 Claude 的"思考 + 报告"双层结构)

### 第一层:思考过程(简要,500 字内)
- 整体看完的"第一印象"
- 哪些维度最强 / 最弱
- 跨文件的"系统性问题" vs 局部问题

### 第二层:结构化报告(主体)

```markdown
# 评审报告 · Vibe-Coding SOP v1

## 整体评分:X/10
- 7 维度评分:
  - 完整性: X/10 — 1 句话总结
  - 可执行性: X/10 — 1 句话总结
  - 可拍板性: X/10 — 1 句话总结
  - 可量化: X/10 — 1 句话总结
  - 可适配: X/10 — 1 句话总结
  - 文档质量: X/10 — 1 句话总结
  - 跨工具兼容: X/10 — 1 句话总结

## 必改(3-5 条,按影响排序)

### 必改 1: [标题]
- **位置**:`SKILL.md:42`(原文:"...")
- **问题**:具体描述 + 为什么是问题
- **触发场景**:在什么情况下会出问题
- **建议修改**:具体怎么改(给改后版本)
- **二阶效应**:改完会不会有副作用
- **影响**:改完的收益

### 必改 2: ...

## 建议改(3-5 条)

### 建议 1: ...
- 位置 + 问题 + 建议(简版)

## 跨文件系统性问题
- 哪些问题不是单个文件的,是跨文件的"模式问题"
- 例:"4 种分发格式都重复了 5 阶段描述,改一处要同步改 4 处,违反 DRY"

## 整体评价(500 字内)
- 这套 SOP 的核心价值
- 最大的风险
- 是否值得发布
- 推荐下一步行动
```

## 关键原则
- ❌ 不要说"可以更好" / "建议完善" — 空话
- ❌ 不要列 10+ 条"必改"— 挑最关键的 3-5 条
- ✅ 发挥你的长处:深度推理,二阶效应,跨文件模式识别
- ✅ 给"可执行的修改建议"(直接给改后版本,不是"应该改为...")
- ✅ 标注"信心等级"(你对这个评价有多大把握:高/中/低)
```

## 用法步骤

1. **打开 Claude.ai**:https://claude.ai/
2. **新对话**:点 "New chat"
3. **粘贴 prompt**:把上面"```"之间的内容全部粘贴
4. **上传 zip**:点附件图标 → 上传 `vibe-coding-sop-dist.zip`
5. **发送**
6. **保存结果**:复制整个回复(包含思考 + 报告),保存为 `claude-eval-2026-07-23.md`

## Claude 特性利用

- **长上下文**:Claude 能吃 100K+ token,你可以直接粘贴 SOP 全文(不限于 zip)
- **深度推理**:Claude 擅长"为什么这是个问题",问它"如果不改会怎样"
- **Artifacts**:Claude 可以输出代码 artifact,你可以让它生成"修改后的 SKILL.md 完整版"
- **Projects**:你可以建一个 Project 把 SOP 放进去,以后每次评审都基于这个 context

## 注意事项

- Claude 偶尔会"过度谨慎" / "过度同意" — 如果发现评价太软,追问"你刚才说 X 没问题,但 Y 场景下会有问题,重新评审"
- Claude 引用文件:行号偶尔会偏移,**自己打开文件复核**
- 如果 Claude 输出"Extending thinking" 太多,可以追问"直接给结论,不要太多 thinking"
